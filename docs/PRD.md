# PRD 文件：生活目標追蹤 + 打怪系統

## 1. 專案概述

### 背景與動機
在日常生活中，許多人會設定目標或列出待辦清單，但傳統的工具往往過於枯燥，缺乏即時的反饋與成就感，導致使用者容易半途而廢。本專案旨在將「自我管理」與「RPG 遊戲元素」結合，將抽象的目標具象化為需要挑戰的「怪物」。透過完成任務來扣除怪物血量、獲取經驗值與獎勵，讓提升自律的過程像在玩遊戲一樣有趣。

### 目標用戶
- **高中生與大學生**：習慣遊戲邏輯，需要動力來完成學業任務。
- **自律初學者**：想培養習慣但容易覺得挫折的人。
- **拖延症患者**：需要「即時反饋」來對抗拖延行為。
- **RPG 遊戲愛好者**：喜歡升級與收集要素的人。

### 核心價值主張
「將每一項任務，都變成一次冒險。」——讓枯燥的日常事務，轉化為熱血的升級之路。

---

## 2. 功能需求

| 功能模組 | 使用者故事 (User Story) |
| :--- | :--- |
| **任務管理** | 作為一名冒險者，我希望能夠新增、編輯與刪除日常任務，以便我規劃我的冒險日程。 |
| **怪物系統** | 作為一名冒險者，我希望在完成高難度任務時遇到更強大的怪物，以便讓我感受到挑戰性。 |
| **戰鬥系統** | 作為一名冒險者，我希望在我勾選完成任務時，系統能自動扣除怪物的血量，以便我看到我的戰鬥成果。 |
| **角色成長** | 作為一名冒險者，我希望在擊敗怪物後獲得經驗值並提升等級，以便讓我的屬性（如攻擊力）變強。 |
| **成就與獎勵** | 作為一名冒險者，我希望擊敗特定怪物後能獲得金幣或勳章，以便我可以在商店購買虛擬道具或解鎖新稱號。 |

---

## 3. 非功能需求

### 技術限制
- **後端框架**：使用 Flask (Python)。
- **前端模板**：使用 Jinja2 配合 HTML/CSS/JS。
- **資料庫**：使用 SQLite，方便小型部署與本地儲存。
- **開發規範**：需符合 RESTful API 設計原則。

### 效能與安全考量
- **響應速度**：勾選任務後的戰鬥動畫與反饋應在 500ms 內觸發。
- **安全性**：基本的帳號密碼加密儲存，確保使用者進度不會被隨意竄改。
- **資料完整性**：任務刪除時，需確保相關連的戰鬥記錄也能正確處理。

---

## 4. MVP 範圍

### Must Have (必要)
- 使用者註冊與登入系統。
- 基礎任務管理 (CRUD)。
- 怪物資訊顯示 (名稱、圖片、血量)。
- 完成任務 -> 扣除怪物 HP -> 擊敗怪物 -> 獲得經驗值。
- 基礎個人檔案 (等級、目前經驗值)。

### Should Have (應該有)
- 怪物種類區分（例如：簡單任務對應史萊姆，困難任務對應惡龍）。
- 戰鬥日誌 (記錄哪一天打了哪隻怪)。
- 簡單的技能系統（例如：累積完成 3 個任務可發動「暴擊」）。

### Nice to Have (以後再說)
- 道具商店 (可用金幣購買頭像框或背景)。
- 全域排行榜 (看看誰是本週最強冒險者)。
- 寵物系統 (幫你一起打怪)。

# PRD — 生活目標加打怪系統

## 1. 專案概述
- **背景與動機**：傳統的代辦清單或打卡工具雖能記錄進度，但缺乏趣味性與成就感，容易讓使用者失去興趣。因此，本專題希望結合遊戲化設計，將日常任務轉換為「打怪升級」的形式，讓使用者在完成目標的同時獲得成就與興趣。
- **目標用戶**：高中生、大學生。這群用戶面臨課業、社團與生活瑣事等多重壓力，需要有趣的方式來激勵自己完成日常任務。
- **核心價值主張**：將無聊的日常代辦事項遊戲化，透過打怪、升級與獎勵機制，提升用戶完成目標的動力與樂趣。

## 2. 功能需求
1. **任務建立與管理**
   - 作為 **高中生/大學生**，我希望 **能夠輕鬆建立並編輯我的日常任務清單**，以便 **我能清楚掌握每天要完成的事情**。
2. **任務完成與打怪機制**
   - 作為 **玩家（使用者）**，我希望 **在勾選完成任務時能看到角色攻擊怪物並獲得經驗值**，以便 **我能感受到努力的實質回饋與成就感**。
3. **角色升級與數值系統**
   - 作為 **玩家（使用者）**，我希望 **我的角色能夠隨經驗值累積而升級變強**，以便 **我有持續完成任務的長期動力**。
4. **怪物系統與關卡**
   - 作為 **玩家（使用者）**，我希望 **能挑戰不同種類與難度的怪物**，以便 **保持遊戲的挑戰性與新鮮感**。
5. **成就展示與獎勵**
   - 作為 **收集控玩家**，我希望 **能解鎖成就或獲得特殊稱號**，以便 **我能展示我的努力成果並滿足收集慾望**。

## 3. 非功能需求
- **技術限制**：系統基於 Web 技術開發，使用 Flask 作為後端框架，搭配 Jinja2 模板引擎進行前端渲染，並採用 SQLite 作為關聯式資料庫儲存資料。
- **效能與安全考量**：
  - **效能**：頁面載入與操作回應時間需快速順暢，確保打怪回饋即時。
  - **安全性**：使用者密碼需經過加密儲存（如 bcrypt），並實作基本的權限控管與防護（防止 SQL Injection 與 XSS），確保每位使用者只能存取自己的任務與角色資料。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**：
  - 使用者註冊、登入與登出系統。
  - 任務清單的 CRUD（新增、讀取、更新、刪除）。
  - 點擊完成任務能扣除怪物血量並獲得經驗值。
  - 基礎的角色狀態顯示（等級、經驗值條、當前遭遇的怪物）。
- **Should Have (應該有)**：
  - 任務難易度分類，不同難度給予不同經驗值。
  - 怪物連續推進機制（怪物死亡後出現下一隻）。
  - 簡單的打怪視覺回饋或動畫效果。
- **Nice to Have (可以有)**：
  - 金幣商城系統與裝備道具購買。
  - 角色外觀客製化。
  - 朋友排行榜或社交分享功能。
